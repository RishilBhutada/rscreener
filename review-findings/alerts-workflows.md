# Review: phone alerts and the data-safety side of the workflows

Read-only review of `main` at `7edb3f8cf` (5-Nov-2026): every script in `alerts/`, the data-safety logic of
`nightly.yml`, `results.yml`, `refetch.yml`, `alerts.yml`, `deploy.yml`, and `pipeline/merge_stored_db.py`,
`merge_newest.sh`, `guarded_fetch.sh`. Nothing was run against ntfy, NSE, Yahoo or any broker.
The fixes of 4/5-Nov (screen-alert 3-night rule, announcements every 20 minutes, the stored-database merges
PR11-3/PR12-8, refetch moving only its own tables) are not re-reported.

**Read-only toward markets: confirmed.** No script calls an order, GTT, funds or position endpoint. The only
broker code is `pipeline/fetch_ncdex.py`, which uses Angel One's login, logout, candle and quote calls only.
(See #18 for the one caveat: the login it uses could trade, even though the code never does.)

**Secrets in logs: none found.** Alert scripts print only error types, never the key or token; the ntfy topic
appears only inside URLs that GitHub masks.

CONFIRMED = seen in the code. PLAUSIBLE = the code allows it; whether it happens depends on live behaviour
that was not checked.
